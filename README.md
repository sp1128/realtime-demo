# 中英文电话 AI 语音通话

本地网页版的实时语音对话，能把 AI 的声音路由到虚拟声卡（比如 VB-CABLE），
从而在各种通话场景里让 AI 替你说话。支持中英文、打断、环境音。

页面上选语种即可：中文走 `lib/prompt.js`，英文走 `lib/prompt.en.js`，
音色列表、称呼校验、分句阈值、TTS 语种锁定会跟着一起切。

## 架构

```
客户说话
   ↓
浏览器采音 (24kHz PCM)
   ↓
本地 Node 服务
   ├─ VAD          谁在说话 / 什么时候接话 / 要不要打断
   ├─ 火山流式 ASR  听懂说了什么（降到 16kHz 再送）
   ├─ DeepSeek LLM 流式生成回复（中/英各一份提示词）
   ├─ 分句切分器    边生成边切句（中英阈值不同）
   └─ 火山流式 TTS  一句一句合成
   ↓
原路回浏览器，排进播放时间轴
   （可选：叠一层电话窄带环境音）
   ↓
客户突然说话 → VAD 触发 → 按住播放 → 等 ASR 确认
   ├─ 听到字了：丢掉未播音频 + 掐断 LLM + 结掉 TTS 会话
   │             + 按已播毫秒数把 AI 那句话截断写回历史
   └─ 没听到字：接着播，一个字不漏
```

**之前用的是 OpenAI Realtime 的端到端语音**（一条 WebSocket 进去，音频进音频出）。
换掉的原因是那条链路是个黑盒：语气和指令遵循都不稳，出了问题只能调 VAD 参数碰运气。
拆成三段之后每段都能单独换供应商、单独看中间结果、单独调参。

代价是首字延迟从 ~0.6s 涨到 ~1.0~1.5s。电话销售场景这个交换是划算的。

### 为什么三段都走国内直连

三跳里每跳走代理都要白搭 200~400ms。实测本机到火山直连 **22ms**，DeepSeek 同样是国内接口，
不该绕出境。语音那两跳数据量大、来回频繁，绕出境的话首字要 2 秒以上，电话里没法听。

LLM 那一跳只付一次首 token 延迟，而且能被 TTS 的播放时间盖掉一部分——
第一句一出来就开始播，后面的 token 是在客户听第一句时悄悄生成的。

跑 `npm run check-proxy` 会分别体检这两条路。

## 一、准备工作

1. Node.js 18 以上：https://nodejs.org
2. **火山引擎语音**：控制台 https://console.volcengine.com/speech/app，
   左侧「API服务中心」里开通这两项，拿到一对 AppID / AccessToken（两个服务共用）：
   - 豆包流式语音识别模型 2.0
   - 豆包语音合成模型 2.0
3. **DeepSeek API Key**：https://platform.deepseek.com/api_keys
4. （可选，接入 LINE 才需要）VB-Audio Virtual Cable

两个服务必须开在**同一个应用**下，否则 AppID 对不上，其中一路必然 401。
凭据在服务详情页下方的「服务接口认证信息」区块。

### 资源号（最容易踩的坑）

1.0 和 2.0 是两套完全不同的写法，代码默认用 2.0：

| | 资源号 |
|---|---|
| ASR 2.0 小时版 | `volc.seedasr.sauc.duration` |
| ASR 2.0 并发版 | `volc.seedasr.sauc.concurrent` |
| TTS 2.0 | `seed-tts-2.0` |
| TTS 2.0 声音复刻 | `seed-icl-2.0` |
| TTS 1.0 声音复刻 字符版 | `seed-icl-1.0` |
| TTS 1.0 声音复刻 并发版 | `seed-icl-1.0-concurr` |

握手被拒时按状态码判断该改哪儿：**400 = 这个号根本不存在**（多半是 1.0/2.0 搞混），
**403 = 号是对的但你没开通这个套餐**。

ASR 2.0 只在 `/api/v3/sauc/bigmodel_async` 上工作，老的 `/bigmodel` 直接 400。
这条地址同时也是官方推荐的「双向流式优化版」，首字和尾字时延都更好，算是被迫用上了更快的那条。

页面勾「用我自己复刻的音色」时，资源号由页面下拉框决定，不必改 `.env`。

### 音色

**页面上直接选**，一百六十多个音色都在 `public/voices.json` 里。
切对话语种时列表会跟着筛：中文通话只出中文音色，英文只出英文音色
（中文音色念英文会带明显口音，反过来也一样）。

- 顶上有个筛选框，可以打「男」「女」「客服」「沉稳」，或者直接搜 code
- 「▶ 试听」放的是火山官方的示例音频，**不消耗你的合成额度**
- 选中的会记在浏览器 localStorage 里，下次打开还是它
- 通话中锁定，要换先挂断——TTS 会话已经按当前音色开出去了，中途换只会让下一轮突然变个人说话

页面选的会覆盖 `.env` 里的默认值：

- 中文默认 `VOLC_TTS_SPEAKER`（`zh_female_vv_uranus_bigtts`）
- 英文默认 `VOLC_TTS_SPEAKER_EN`（`en_male_tim_uranus_bigtts`）
- 没在页面里挑过音色时，服务端按语种取对应那一个

分组里第一档「电话场景常用」是按名字和场景标签挑出来置顶的，**不是官方推荐**，
实际还得自己听。**音色对信任感的影响比话术还大**，值得花十分钟挨个过一遍。

想换成控制台里新开通的音色，去「音色详情」表格复制 `Voice_type` 那一列，
加进 `public/voices.json` 即可。注意**音色和模型版本绑死**：2.0 的音色是
`_uranus_bigtts` 结尾或 `saturn_` 开头，老的 `_moon_bigtts` / `_mars_bigtts`
拿到 `seed-tts-2.0` 上会失败。加之前最好真连一次双向流式——控制台会列出
一些双向流式根本不支持的音色，选中了要到通话第一句才报 `45002000`。

### 用自己复刻的音色

页面上勾「用我自己复刻的音色」，填音色 ID（通常 `S_` 开头），再选资源号：

- **复刻 2.0**（`seed-icl-2.0`）——默认，要单独开通「豆包声音复刻模型2.0」
- **复刻 1.0 字符版**（`seed-icl-1.0`）
- **复刻 1.0 并发版**（`seed-icl-1.0-concurr`）

代码会按你选的资源号发请求，跟官方精品音色的 `seed-tts-2.0` 不通用。
没开通对应套餐的话建连直接 403，页面会明确提示是这个原因（而不是让你去查 `.env`）。

旁边那个 model 档位**建议留空**。实测只有 `seed-tts-2.0-standard` 合法，
把资源号填进 model 会直接报 `45000001 InvalidModel`——用哪一代复刻是资源号决定的。

复刻的两条路：

1. **控制台**：`console.volcengine.com/speech/app` →「豆包声音复刻模型2.0」，
   传一段样音，出来一个 `S_xxxxxxx`
2. **API**：`POST https://openspeech.bytedance.com/api/v3/tts/voice_clone`，
   body 里 `audio.data` 传 base64 音频、`language: 0`（中文）、
   `extra_params.demo_text` 是试听文本。返回 `speaker_id` 和一小时有效的
   `demo_audio` 试听链接，`status` 到 2 或 4 才能拿去合成

样音要求：≤10MB，wav/mp3/ogg/m4a/aac/pcm（pcm 只收 24k 单声道）。
可以带 `text` 参考文本，服务端会比对念得像不像，差太多会返回 `45001109 WERError`。
样音噪声大就开 `enable_audio_denoise`；想让合成音色更贴近样本，
关掉 `disable_volume_normalization`。

⚠️ **计费提醒**：官方文档明确写了「首次调用合成接口即视为转正并收取音色槽位费」。
所以先用训练接口返回的 `demo_audio` 听效果，确认满意了再拿到这个项目里正式合成。

## 二、安装

**这个项目统一用 npm**（仓库里只有 `package-lock.json`）。

```bash
npm install
```

`preinstall` 里有道防呆：用 pnpm/yarn 装依赖会被拦下并提示改用 npm。
拦的只是 `install`——`pnpm start` 这种代跑脚本的用法不碰 `node_modules`，随便用。
理由是 `pnpm install` 会另生成一份 `pnpm-lock.yaml`，两份 lock 并存之后
解析出的版本迟早对不上，而且往往到别人机器上才爆。

```bash
cp .env.example .env
```

Windows 没有 `cp` 的话：

```powershell
Copy-Item .env.example .env
```

打开 `.env`，至少填这三行：

```
VOLC_APP_ID=你的AppID
VOLC_ACCESS_TOKEN=你的AccessToken
DEEPSEEK_API_KEY=sk-你的DeepSeek密钥
```

**资源号要跟你实际开通的套餐对上**，填错会在 WebSocket 握手阶段就被拒（401/403）。
默认值是 ASR 小时版 + TTS 双向流式，用的是并发版或单向流式的话去 `.env` 里改。

完整旋钮都在 `.env.example` 里，下面「七、调参」只挑通话里会碰到的讲。

## 三、启动

```bash
npm start
```

改代码时可以用 `npm run dev`（`node --watch`，存盘自动重启）。

启动日志会把当前链路和关键旋钮打出来，省得改完 `.env` 还要猜有没有生效：

```
链路 火山ASR(volc.seedasr.sauc.duration) → deepseek-chat → 火山TTS(seed-tts-2.0 / zh_female_vv_uranus_bigtts)
轮次 静音300ms提交（阈值2.6倍底噪）｜打断 确认式，1000ms内听到2字算数｜ASR定稿400ms
```

然后用 Chrome 打开 http://localhost:3000

### 用手机体验（和电脑同一 WiFi）

浏览器只给 **https** 或 **localhost** 麦克风权限，所以服务会额外开一个自签 HTTPS。启动后看日志里的地址，例如：

```
https://192.168.0.101:3443
```

1. 手机浏览器打开这个地址（不要用 `http://`）。
2. 证书是本机自签的，页面会报警：Chrome 点「高级」→「继续前往」；Safari 点「显示详细内容」→「访问此网站」。
3. 点「开始通话」时允许麦克风。输入选手机麦克风，输出用默认听筒/扬声器。
4. 打不开时：关掉路由器的「AP 隔离 / 访客网络」；Windows 防火墙放行 Node.js，或放行 TCP `3443`。

电脑自己测仍然用 `http://localhost:3000`，不用走 HTTPS。端口可用 `.env` 里的 `HTTPS_PORT` 改。

## 四、页面怎么用

1. 允许麦克风权限。
2. **对话语种**：中文 / English。通话中不能改。切语种会同时改：
   - 提示词（`lib/prompt.js` / `lib/prompt.en.js`）
   - 音色列表（只留当前语种）
   - 称呼校验和占位示例
   - TTS 的 `explicit_language`（`zh-cn` / `en`），避免自动语种检测把声线漂走
3. 两个设备下拉框：
   - **输出设备**：AI 的声音放到哪里。自己测就选耳机；接 LINE 选 **CABLE Input**。
   - **输入设备**：能听到对方声音的那一路。接 LINE 时选 **CABLE Output** 或立体声混音。
4. **AI 音色**：按当前语种筛选。旁边「▶ 试听」可以先听样音（走的是官方示例音频，不花钱）。
   试听同样按上面选的输出设备走，所以接了 CABLE 的话对方也听得到。
   要走自己复刻的音色，勾「用我自己复刻的音色」，填 ID 并选资源号。
5. **填「对方称呼」**——不填不让拨号。这个值会替换掉提示词里所有的 `{{称呼}}` 占位符，
   AI 开场就用它称呼对方。
   - 中文：2~20 个汉字或字母，如「叶升辉先生」「王女士」「李经理」
   - 英文：字母开头，可含空格、点和连字符，如 `Mr. Smith` / `Ms. Chen` / `David`
6. **通话环境音**（可选）：办公室 / 咖啡馆 / 街边 / 车里，或「随机」（每通抽一个）。
   垫在 AI 声音后面，末端低通到 3.4kHz（电话窄带）。滑块调响度；
   默认只在 AI 说话时淡入，勾「全程播放」则一直垫着。素材是 CC0 实地录音，
   出处见 `public/ambience/来源.md`。
7. 点「开始通话」。默认 AI 会先开口（外呼场景），想让客户先说话就在 `.env` 里
   设 `AUTO_GREET=false`。
8. 下方实时显示双方文字，还有「对方 / AI」两条音量表。AI 的文字总是跑在声音前面一点——文本先生成，音频随后合成。

另外几个按钮，都不必接通话也能用（录制除外）：

| 按钮 | 做什么 |
|---|---|
| 🔊 测试输出 | 走跟 AI 完全一样的输出通路放一段警笛声，用来确认 CABLE / LINE 通不通 |
| ⏺️ 录制 AI 语音 | 从声卡之前的汇聚点录无损 WAV。拿它跟对方实际听到的对比，能分清是模型本身如此还是线路损耗 |
| 📶 测线路 | 不打 LINE、不碰声卡，让 AI 自说自话 15 秒，量首字延迟和供给率 |
| 调试模式 | 把采集参数、收发包统计打到日志里 |

开场白每通电话措辞都不一样（`GREET_STYLES` / `GREET_STYLES_EN` 随机挑一个措辞方向），
但要办的三件事不变：确认是不是本人、说明你是谁、请对方给一分钟。
**姓名是锁死的**——放开措辞之后模型会连姓名一起"创作"，实测编出过张先生、陈先生、
陈建国先生。现在称呼由页面在拨号前填，替换提示词里的占位符，
并在开场提示里明确"只能用这个"。

称呼会被拼进提示词，所以服务端按语种限制字符集（`server.js` 的 `name` 参数校验），
挡掉引号、换行和其它标点——这些才是能跳出上下文的字符。填了但不合法时，
页面会提示服务端不认，这通回落到提示词里的默认名（中文「叶升辉先生」、英文 `Mr. Smith`）。

临时整份换掉中文话术可以用 `.env` 的 `AGENT_INSTRUCTIONS`；英文话术改 `lib/prompt.en.js`。
平时直接改对应文件更方便。

## 五、和 LINE 配合

1. 本 Demo 的"输出设备"选 **CABLE Input**
2. LINE 的麦克风改成 **CABLE Output**

⚠️ 这种接法下 LINE 只会传 AI 的声音，你自己说话不会被传过去。想要"AI + 你"同时传，
需要 VoiceMeeter 之类的混音工具把两路混合后再作为 LINE 的麦克风来源。

接好之后先点「🔊 测试输出」，问对方听不听得到，再开始通话。
环境音和试听也会走这条输出，接了 CABLE 的话对方都能听到。

## 六、连不上怎么办

```bash
npm run check-proxy
```

会分别测两条路，各测 8 次，走完 TLS 才算成功。

**为什么不能只看"代理有没有反应"**：Clash 这类代理收到 `CONNECT` 会立刻回
`200 Connection established`，这时它根本还没去拨上游。真正的成败要等隧道里的
TLS 握手才暴露。所以脚本一定要走完 TLS。

常见故障：

| 症状 | 原因 |
|---|---|
| 页面报 401 | 火山的 AppID/Token 不对，或 DeepSeek Key 不对 |
| 页面报 403 | 火山资源号跟实际开通的套餐对不上，改 `VOLC_*_RESOURCE_ID`；勾了复刻音色则是没开通对应的复刻服务 |
| 火山也慢到 300ms | 开了**系统级全局代理**，把国内流量也绕出境了。改成规则模式 |
| AI 某几轮干脆不接话 | DeepSeek 那一跳被代理绕慢或绕挂了，先直连再查 |
| 英文开场声线漂、夹中文腔 | 页面语种没切到 English，或仍在用中文音色 |

页面上的 **📶 测线路** 按钮单独测 LLM→TTS 这一段，不用打 LINE、不碰声卡，
让 AI 自说自话 15 秒。要看三件事：

- **首字延迟**：触发到第一个音频包。里面套着 LLM 首 token + TTS 首包两段。
  看"最快"那一轮，第一轮带预热不算数。<1500ms 好，>3000ms 电话里会觉得冷场。
- **轮内断流**：一轮话说到一半的最大空档。跨轮的空档是模型在思考，不算线路问题。
- **供给率**：音频到达速度 ÷ 实时。**大于 100% 是好事**，说明缓冲越垫越厚；
  小于 100% 才会卡。

## 七、调参

### 接话太慢 / 抢白

`.env` 里这几个：

- `VAD_SILENCE_MS`（默认 300）：静音多久算客户说完。小了客户喘口气就被抢白，大了发木。
- `COMMIT_DELAY_MS`（默认 150）：静音后再等一下让 ASR 最后一段落地。
  调小会丢客户最后两三个字。这两个加起来必须大于 `ASR_END_WINDOW_MS`（400），
  否则提交时 ASR 还没定稿。
- `VAD_RATIO`（默认 2.6）：要超过噪声底多少倍才算人声。环境嘈杂调到 3.5~5。
- `ASR_END_WINDOW_MS`（默认 400）：ASR 内部静音多久定稿，跟上面两个对齐才赶得上提交。

噪声底是自己长出来的——空调、风扇这类稳态噪声会被自动吸收进去，一般不用手工调。

### AI 被自己的声音打断（走 CABLE 回环时最容易出）

这是级联架构最典型的坑，realtime 时代是 OpenAI 那边替你处理的。

浏览器侧会按输入设备自动决定要不要开 AEC（`public/index.html` 的 `startCapture`）：

- **真人麦克风**（手机、耳机麦）：打开回声消除 / 降噪 / 自动增益。免提时扬声器里的 AI 声会灌进麦，不消回声就会打不断。
- **线路输入**（CABLE、立体声混音、虚拟声卡）：这三项故意关掉。输入是线路信号，不是真人麦，Chrome 那套为麦克风设计的处理套上去会把对方的声音削得断断续续。

线路输入时回声全靠下面几层扛：

1. AI 说话期间进入回声模式：把扬声器漏进麦的能量当成底噪，只有明显更大的声音才算插话
   （`lib/vad.js` 的 `setGuard`）。免提时尤其依赖这一层。
2. AI 说话时不把麦克风送给 ASR，避免把自己的词识别成客户在说。
3. **确认式打断**：VAD 响了只是"按住播放"，要等 ASR 真吐出 ≥2 个字、且不像正在念的稿子，才执行完整打断。
   按住期间音频是扣在浏览器手里的，误报了原样接回去，一个字不漏。
4. **预滚动**（`PREROLL_MS`，默认 500）：VAD 要连续几帧才确认有人在说话，这段时间的音频已经被当静音喂掉了；
   打断触发时把这几百毫秒补送给 ASR，否则 ASR 从半个字开始听，很难在确认窗口内出字。

还是被误打断就把 `BARGE_MIN_CHARS` 调到 3，或 `VAD_RATIO` 调高。
反过来，如果真打断时反应太慢，把 `BARGE_CONFIRM_MS` 调小。

**回声比对为什么对短词网开一面**（`BARGE_ECHO_MIN_CHARS`，默认 5）：
`_looksLikeEcho` 拿客户说的话跟 AI 正在念的那一两句比，像就当回声。
但选择题抢答恰恰长在那句里——AI 问「做股票、期货还是数字资产」，客户答「期货」，
一比对就被判成回声，打断不成立，1 秒后连这句一起被清掉，客户等于白说了。

所以短于这个长度的转写一律放行。敢这么放是因为回声的主力防线不在这儿：
AI 说话时 ASR 吃的是静音，打断一触发就暂停播放，能混进来的只有声卡里那一两百毫秒尾巴。
两种错的代价也不对等——吃掉抢答是静默失败（客户以为没听见），
误打断只是 AI 停一下再听。真被误打断得多，把这个值调小。

手机免提：页面采集已打开浏览器 AEC。仍可能漏一点，所以服务端还有上面几层。尽量让手机离嘴近一些、音量不要开到最大。

说完后客户一直不接话，大约 4 秒会追问一句；再大约 10 秒还不说话就道别并结束通话
（`IDLE_NUDGE_MS` / `IDLE_BYE_MS`）。

追问分两种情况：

- **开场就没人应**：走固定句「喂，叶先生，能听到吗？」（英文是 `Hello? Is this …?`）。
  这时候是在确认线路通不通，没有上下文可结合，固定句最合适。
  称呼取页面传入的值，不填就用提示词默认名。
- **对话中途冷场**：让 LLM 结合上下文生成，固定句在具体语境里容易显得突兀。

中途追问的生成有三道保险，因为这一步很容易翻车：

1. **指令用 user 角色发**，不是 system。历史里最后一条是 assistant，再追加 system
   的话模型会接着往下写对话的下一轮——也就是客户的台词。实测踩过：AI 问完
   "平时有做股票期货吗"、冷场之后自己接了句"嗯，平时自己会炒点股票"。
2. **不流式**。先拿全文校验合格再出声。追问就十几个字，等全文代价很小。
3. **校验不过退回固定句**。要求：短、单句、必须是问句、不能跟上一句重复。
   "必须是问句"这条最管用——模型替客户答话时输出的往往是通顺的陈述句，长度完全合规。

超过 `NUDGE_TIMEOUT_MS`（默认 1500ms）也退回固定句，冷场已经够久不能再干等。

道别那句仍走固定句：它是整通电话的最后一句，最不该出意外。

### 听出客户急不急

级联架构最大的损失是模型只看得到文字、听不出语气。`ASR_EMOTION` 默认开，
会在定稿分句上多带情绪 / 语速 / 音量，塞进给 LLM 的提示里
（日志里那行 `🎚️ 语气`）。免费，只是多几个字段。

实测语速能区分（不耐烦 5.0 / 平静 3.8）；情绪标签在合成语音上一直是 `neutral`，
真人语音上效果待观察。下游以语速为主、情绪为辅。嫌不准就设 `ASR_EMOTION=false`。

### 同一个音色听起来像好几个人

`.env` 里的 `VOLC_TTS_STYLE`（英文是 `VOLC_TTS_STYLE_EN`）是一句大白话语音指令，
发给 TTS 的 `context_texts`，用来把语气收窄。默认那句是冲着"平稳、别起伏"去的。
设成空字符串就关掉。这段文字不计费，仅 TTS 2.0 音色支持。

另外 TTS 整通电话共用一个 `section_id`，让前后几轮的节奏连贯，而不是每轮重新起调。

### 首字延迟偏高

按贡献从大到小排：

1. `VAD_SILENCE_MS` —— 这是最大头，300ms 里有 300ms 是纯等
2. LLM 那一跳被系统代理绕远了，`npm run check-proxy` 看握手耗时
3. 分句器的 `firstMin`（`lib/chunker.js`）——第一句攒够长度才送 TTS
4. `LLM_MODEL` 换个更快的——思考模型（`deepseek-reasoner`）首字会慢很多

### 首字延迟的实测分布（中文）

```
VAD 判停        300 ms   纯等
提交延迟        150 ms   纯等，让 ASR 定稿赶上
LLM 首 token   ~520 ms   ← 最大头
分句 + TTS 首包 ~530 ms
播放抖动缓冲     90 ms
────────────────────────
客户感知        ~1590 ms
```

### 火山 TTS 有个长度阈值，别切太碎

实测：只送一段文本、不调 `finishSession`，**不够长它根本不开始合成**。
这个门槛中英差很多：

```
中文  「嗯。」          3.5 秒内没有音频
      「嗯，好的。」     339ms 出声
      13 字            253ms 出声

英文  6 词 / 35 字符    3.5 秒不出声
      11 词 / 64 字符   1856ms
      26 词 / 145 字符  358ms
```

所以 `lib/chunker.js` 按语种分开设：中文 `firstMin=6`，英文 `firstMin=55`。
曾经中文设成 2，想着"开头两三个字尽早送出去"，实际是每轮第一块都把 TTS 卡住，
一直等到第二块到达凑够长度才出声。改成 6 之后首字延迟从 1530ms 降到 1300ms。
英文如果沿用中文那套数字，每轮开头都会卡两秒。

同理，**用垫话（「嗯，」）盖住 LLM 等待这条路在这里走不通**：短垫话自己就要卡住；
换成够长的垫话能立刻合成，但它的音频只有一秒多，播完到正文到达之间
仍有几百毫秒空白，听感是"嗯，……（停顿）……正文"，比直接等还难受。
`FILLER_MS` 留了开关但默认 0。

**别改成逐字喂 TTS。**官方 demo 是逐字发的，看着更"流式"，但实测同一句话：
按句发首个音频包 309ms，逐字发 422ms。原因是逐字发时 TTS 要等攒够一个语义单元才能起头，
而分句器直接给它一个完整单元。

### 打断截断准不准

TTS 的字级时间戳（`enable_subtitle`）是**整句念完才回**的，所以：

- 打断发生在「已经念完的句子」之后 → 精确切到字
- 打断发生在正在念的那句中间 → 退化成按音频时长比例估算

多句回复时前面几句都能精确对齐，只有最后那句是估的。单句回复则全靠估算。
这个精度对"让模型知道自己讲到哪儿"已经够用，不用为它做额外工作。

### AI 话太多 / 太啰嗦

先改提示词（中文 `lib/prompt.js`、英文 `lib/prompt.en.js`），`MAX_OUTPUT_TOKENS` 只是兜底闸门。
设太小会把话切断在半句，电话里很难听。

### 多音字读错

中文提示词里逐个标了正确读音。你的话术里有别的专有名词照那个格式往里加。
另外把这些词填进 `.env` 的 `ASR_HOTWORDS`，那是给识别侧用的，两边都要管。
代码里已经预置了量化、回测、风控这几个话术高频词，`.env` 里的会并进来。

## 八、代码结构

```
server.js              接线：HTTP + HTTPS + WebSocket + 配置读取，没有业务逻辑
lib/session.js         编排器。状态机、轮次判断、打断、上下文管理都在这
lib/vad.js             能量 VAD，自适应噪声底
lib/volc-asr.js        火山流式 ASR 客户端
lib/volc-tts.js        火山双向流式 TTS 客户端
lib/llm.js             DeepSeek 流式对话（OpenAI 兼容协议，手写 SSE）
lib/chunker.js         分句切分器（中英阈值不同）
lib/resample.js        24kHz → 16kHz 降采样
lib/protocol.js        火山二进制帧编解码
lib/prompt.js          中文角色设定，并按语种分发到英文版
lib/prompt.en.js       英文角色设定
lib/lan.js             局域网 IP + 自签证书
public/index.html      前端。只管采音、放音、汇报，不做任何决定
public/voices.json     音色清单（按语种筛），页面下拉框的数据源
public/ambience/       环境音素材（CC0）
```

前端能调的两个（`public/index.html` 顶部）：

- `PLAY_LEAD_MS`（90）：播放抖动缓冲。通话结束的小结里出现"播放欠载 N 次"就调大它，
  代价是延迟增加同等数值。
- `CHUNK_SAMPLES`（480 = 20ms）：每包音频多少采样点。小一点 ASR 能更早看到人声。

## 九、还能往上加的

火山已经支持、代码里没接的：

- **`corpus.context` 的 `dialog_ctx`**：把最近几轮对话作为上下文喂给 ASR，
  识别准确率会明显提升（模型知道刚才在聊什么）。历史就在 `lib/session.js` 手里，接起来不难。
  热词（`ASR_HOTWORDS`）已经在用同一个 `corpus.context` 字段。

`context_texts`（TTS 语音指令）已经接上，见上面的 `VOLC_TTS_STYLE`。
目前是整通电话一句固定指令；按客户情绪动态切换语气还没做。

## 十、费用

三家分别计费：火山 ASR 按时长、火山 TTS 按字数、DeepSeek 按 token。
TTS 的计费字数会在每轮结束时由服务端返回（代码里已经在收），比 Realtime 的音频 token
便宜不少，但仍然是按用量走的，测试注意控制时长。
环境音和「▶ 试听」不走合成接口，不消耗 TTS 额度。
